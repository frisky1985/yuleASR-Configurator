## 2. 证据链完整性说明

1. **schema 侧**：15 个配置项全部存在于 `verification/extracted-cfgh/`
   对应 schema 的 properties（宏名即参数名），defaultValue 与手写头宏值一致（YAC-VER-001 全量比对零不一致）：
   - NVM_DEV_ERROR_DETECT=True / CAN_NUM_CONTROLLERS=2 / OS_CFG_NUM_TASKS=8 /
     DCM_RX_BUFFER_SIZE=256 / COM_NUM_OF_SIGNALS=256 等（见 YAC-VER-001
     §3.3 抽样）
2. **宏侧**：每行引用均经 `grep -rn` 在 yuleASR `src/`
   实测命中（非自造）；`#include "X_Cfg.h"` 在对应 `.c`
   顶部确认（如 Can.c:23、NvM.c、Dcm.c:20、Com.c、Os_Cfg.c）
3. **功能侧**：所有引用均为数组定长、边界校验、特性编译开关或寄存器配置——配置改变直接改变生成代码布局/行为 → 链条"配置项 → 宏 → 代码分支/数据结构 → 功能"成立
4. **编译侧佐证**：YAC-VER-002 已实测 109 生成头替换后全量编译通过（139/139）+
   ctest 55/55，证明上述宏引用路径在生成产物下真实可编译、可运行

## 3. 抽样观察（如实记录，非缺陷）

| 观察                   | 模块 | 说明                                                                                                                                                                                                                  |
| ---------------------- | ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| API 使能宏已定义未消费 | NvM  | `NVM_SET_RAM_BLOCK_STATUS_API`/`NVM_GET_ERROR_STATUS_API`/`NVM_SET_BLOCK_PROTECTION_API` 等在 NvM_Cfg.h 定义，但当前实现（NvM.c）无条件编译全部 API（无 `#if` 门控）——AUTOSAR 标准配置面完整，消费属 yuleASR 实现现状 |
| 钩子使能宏已定义未消费 | Os   | `OS_CFG_STARTUP_HOOK`/`OS_CFG_ERROR_HOOK`/`OS_CFG_STACK_MONITORING` 等定义于 Os_Cfg.h，src/ 内无消费点（hook 实现走 FreeRTOS 静态钩子 Os_FreertosHooks.c）                                                            |
| 计数宏仅测试消费       | Dcm  | `DCM_NUM_SERVICES`/`DCM_NUM_DIDS`/`DCM_NUM_SESSIONS` 只在 Dcm_test.c 引用，生产分发走协议状态机（DCM_NUM_PROTOCOLS）而非服务表                                                                                        |
