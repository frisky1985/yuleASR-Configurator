## 3. 缺口清单（全部有证据解释，缺口 = 0）

### 3.1 缺失配置项 7 个 → 合理缺省（MemMap 段标记宏，splice 原样保留）

| 模块      | 宏                                         | 性质                  | 证据                                                                                                       |
| --------- | ------------------------------------------ | --------------------- | ---------------------------------------------------------------------------------------------------------- |
| csm       | CSM_START_SEC_CONFIG_DATA_UNSPECIFIED      | MemMap 段标记（空宏） | yuleASR `Csm_Cfg.h:166` 空 define，与 `#include "Csm_MemMap.h"` 成对控制 #pragma section；**非可配置参数** |
| csm       | CSM_STOP_SEC_CODE                          | 同上                  | `Csm_Cfg.h:160`                                                                                            |
| csm       | CSM_STOP_SEC_CONFIG_DATA_UNSPECIFIED       | 同上                  | `Csm_Cfg.h:174`                                                                                            |
| ramsafety | RAMSAFETY_STOP_SEC_CONFIG_DATA_UNSPECIFIED | 同上                  | `Ramsafety_Cfg.h`（splice 非宏段）                                                                         |
| wdgm      | WDGM_START_SEC_CONFIG_DATA_UNSPECIFIED     | 同上                  | `Wdgm_Cfg.h:102`                                                                                           |
| wdgm      | WDGM_STOP_SEC_CODE                         | 同上                  | `Wdgm_Cfg.h:96`                                                                                            |
| wdgm      | WDGM_STOP_SEC_CONFIG_DATA_UNSPECIFIED      | 同上                  | `Wdgm_Cfg.h:115`                                                                                           |

**解释**：这 7 个是 AUTOSAR
MemMap 段开合标记（`#define XXX_START/STOP_SEC[_suffix]`
空宏），不是配置项。codegen 的拼接机制（`KNOWN_MIXED_HEADERS`
27 模块 + 探测护栏）将手写头非宏段原样拼接进生成头，`MEMMAP_SEGMENT_DEFINE_RE`
明确豁免此类行。 **实证**：YAC-VER-002 dry-run 生成的
`Csm_Cfg.h:162/168/176`、`Wdgm_Cfg.h:96/102/115`、 `Ramsafety_Cfg.h:74`
均原样保留上述段标记（替换包 `/tmp/ver002-out/*-apply/generated/`
可查）。→ 判定：**合理缺省，无需补 schema**。

### 3.2 多余配置项 1 个 → 合理缺省（配置容器，叶参数即真实宏）

| 模块 | 参数        | 性质                     | 证据                                                                                                                                                                                                                                                                                                                           |
| ---- | ----------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| boot | OtaSecurity | object 容器（10 叶参数） | `boot.json` OtaSecurity.properties 含 BOOT_SECURE_BOOT_ENABLE / BOOT_SIGNATURE_ALGORITHM / BOOT_ANTI_ROLLBACK_ENABLE / BOOT_CERT_CHAIN_MAX_DEPTH / BOOT_KEY_ROTATION_PERIOD / BOOT_USER_CONFIRM_REQUIRED / BOOT_USER_CONFIRM_TIMEOUT_MS / BOOT_UPGRADE_LOG_ENABLE / BOOT_UPGRADE_LOG_MAX_ENTRIES / BOOT_ROLLBACK_CONFIRM_BOOTS |

**解释**：OtaSecurity 是配置分组容器（YAC-MAP-002
e81a63c9 双源同步引入），容器名本身不是宏；其 **10 个叶参数全部对应 `Boot_Cfg.h`
真实宏**（如 `BOOT_KEY_ROTATION_PERIOD (365U)` = Boot_Cfg.h:23、
`BOOT_SECURE_BOOT_ENABLE STD_ON` =
Boot_Cfg.h:52），codegen 生成时按叶参数输出宏。→ 判定：**合理缺省，无需改动**。

### 3.3 默认值不一致 0 个

109 模块全量比对 schema
defaultValue（归一化：STD_ON/TRUE→true、去括号/后缀、hex/dec 数值比较）vs 手写头宏值，**零不一致**。典型样例（抽查 5 模块）：

- NVM_DEV_ERROR_DETECT：schema `true` ↔ 手写 `STD_ON`
- CAN_NUM_CONTROLLERS：schema `2` ↔ 手写 `(2U)`
- COM_NUM_OF_SIGNALS：schema `256` ↔ 手写 `(256U)`
- OS_CFG_NUM_TASKS：schema `8` ↔ 手写 `(8U)`
- DCM_RX_BUFFER_SIZE：schema `256` ↔ 手写 `(256U)`
